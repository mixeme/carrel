# Безопасность сервера Carrel

Требования — в спеке: [S-29 «Безопасность сводно»](spec/carrel-server.md)
(от чего защищает и от чего нет, маршруты без входа, разбор чужих файлов) и
[C-11 «Инварианты безопасности»](spec/carrel-common.md). Сроки, вёдра и
параметры KDF — таблица «Сроки и лимиты» в [architecture.md](architecture.md).
Здесь — закрытые развилки, аудиты, то, что не пересматривается, и то, что
принято как есть.

**Аудит — Fable**, только безопасность, каждый заход — свой периметр, не
«посмотреть всё». Находки чинит сам аудитор, в своём коммите каждую:
сначала проверка, красная на прежнем коде, потом правка (C-16). Отдельно
уходит только продуктовое решение.

## Закрытые развилки

**Крипто (S-2).** Argon2id; AEAD — XChaCha20-Poly1305. Ключ данных — 32
случайных байта на жизнь учётки. AAD: обёртка `carrel.wrap.v1|<login>`, блоб
`carrel.blob.v1|<login>`, том `carrel.state.v1|<version>`, устройство
`carrel.device.v1|<login>|<id>`, ссылка `carrel.publish.v1|<hash>`, триггер
копии `carrel.backup.v1|<job>`. Две соли — вход и обёртка; параметры KDF
пишутся в запись. `server.key` — 32 байта, `O_EXCL`, `0600`, не
перезаписывается; битый — отказ запуска. Депонирование: X25519 + HKDF-SHA256 +
XChaCha20-Poly1305, эфемерный ключ.

**Том.** JSON внутри AEAD: магия `CRL1`, uint32 версии, 24-байтовый nonce.
Запись — tmp + fsync + rename; журнал аудита — той же операцией. Файл более
новой версии — отказ.

**Сессии.** Только в памяти. Кука `carrel_sid`: HttpOnly, SameSite=Lax,
Secure за доверенным HTTPS-прокси. Новый SID при каждом входе. Кука
`carrel_cols_<раздел>` (S-9.6) — выбор столбцов этого браузера, не секрет и не
данные человека: имена столбцов из закрытого списка, неизвестное
отбрасывается при чтении; атрибуты те же.

**CSRF.** Проверка до обработчика: поле `_csrf` (urlencoded и multipart) или
заголовок `X-CSRF-Token`. После входа — токен сессии. До входа (Ф2-15) —
двойная подача: GET формы ставит куку `carrel_csrf` и то же значение в
`_csrf`, POST сверяет два значения из запроса, серверного состояния нет. В
multipart `_csrf` читается из текстовой части в пределах потолка маршрута;
`X-CSRF-Token` сверяется первым и тело не читает — сценарий может не
буферизовать файл, а без сценариев загрузка работает полем (U-8).

**SSRF.** Резолв → проверка IP (петля, RFC 1918, link-local, ULA, multicast,
CGNAT, IPv4-mapped) → `DialContext` на **этот** IP, `ServerName` — исходный
хост; повтор после каждого редиректа. Встроенный IPv4 из NAT64 и 6to4
проверяется как IPv4; `::/96`, Teredo, `fec0::/10`, `0.0.0.0/8`,
`240.0.0.0/4`, `192.0.0.0/24` — отказ (Ф-1). Allowlist — хосты, не сети.
Учётные данные ставятся до `Client.Do`, чтобы Go снимал `Authorization` при
переходе на чужой хост (Ф-15). Понижение HTTPS → HTTP на исходящем DAV —
отказ.

**Сертификат (Ф-13, решение 05.09.2026).** `http://` и непроверяемый
сертификат — предупреждение, не отказ. `InsecureSkipVerify` глобально нельзя:
продолжение только с отпечатком SHA-256 листового сертификата, принятым на
этом подключении и лежащим в блобе; смена сертификата — новое принятие. Пул
соединений ключуется отпечатком: закреплённый клиент соединения не делит.

**Unlock (S-10.7).** Окно выдачи секретов живёт в сессии (`UnlockUntil`), не в
учётке, открывается только паролем под ведром входа, пишется в журнал. Одни
часы на все выдачи: пароль подключения, профиль устройства, депонирование,
пароль davloom, внешний триггер копии, удаление учётки.

**davloom.** HTTP Basic, realm `davloom`; «нет / неверно / отозвано /
отключено» — один 401 за одно время, неуспех тратит свои вёдра входа. После
unwrap — кэш процесса по SHA-256(логин NUL пароль), каждое попадание
сверяется с `DeviceOf`; отзыв, отключение, wipe и выключение затирают ключи.
Выдача пароля — после unlock; список и отзыв — без. Смена пароля входа
обёртки устройств не трогает.

**Ссылки из текста записи (C-6.9, `v0.2.101`).** Заметку и описание пишет
любой, кто пишет в коллекцию, а `/p/` показывает их кому угодно; ссылка
Markdown — адрес на странице Carrel. `Block.Href` получает только `http` и
`https` с хостом, `mailto` и `tel` (`cal.linkHref`); `javascript:`, `data:`,
`vbscript:`, `file:`, относительный и схемо-относительный адрес, схема в
любом регистре, через `&#58;`, с пробелом, табуляцией или управляющим знаком
впереди — слова ссылки без ссылки. Адрес проверяется таким, каким его
напишет сам goldmark (`util.URLEscape`: ссылки на знаки разрешены, остальное
— проценты), не исходной строкой. Ссылки полей карточки (`Field.Href`)
собирает сервер: `tel:` из цифр, `mailto:` из адреса, сайт — только
`http(s)`. Ссылка `urn:uuid:` на карточку — тоже текст: свой адрес
карточки по ней Carrel пока не строит.

**Секретные ссылки.** Секрет ≥ 32 байт, в состоянии — свёртка, сравнение за
постоянное время. «Нет / использовано / отозвано / истекло / чужое» — один ответ за одно
время: страница rest-1 «This link does not work» (`DeadLinkPage`) с кодом 404,
одни слова, одна дверь на вход и одни заголовки у `/invite/`, `/forgot/`,
`/confirm-email/` и `/p/` (`no-referrer` у них — по семейству адреса, не по
секрету); тем же телом и кодом отвечает `/api/backup/`. 404, а не 410: «не
найдено» верно и о ссылке, которой не было, а «больше нет» сказало бы, что
была. Ведро анонимных токенов стоит до проверки секрета, как стояло. Пароль подключения для `/p` — конверт под `server.key`, только пока
есть живая ссылка на это подключение; пароли всех подключений в состояние не
кладутся. Внешний триггер копии — такой же конверт ключа данных, только если
человек включил его явно: названное снижение защиты.

**Ждут решения владельца (рекомендации аудитора).**

- **А4-5.** `editConnection`: адрес сменился, пароль пуст и метки «без
  пароля» нет — `discover.Run` идёт на новый адрес с сохранённым паролем.
  Кто держит открытый вход (оставленный браузер), получает пароль DAV на
  свой сервер, не набирая пароля Carrel, — то, от чего S-10.7 закрывает
  «Show password». Поведение закреплено проверкой
  `TestEditConnectionAfterPasswordAndAddressChange` («an empty password
  keeps the stored one» при переезде сервера). Рекомендация: при смене
  схемы или хоста (с портом) сохранённый пароль не переносится — поле
  говорит «Type the password: Carrel does not send the saved one to
  another address», как `missingPassword`; правка без смены адреса — как
  была. То же у релея почты администратора (`admin_settings.go`: пароль
  сохраняется при том же пользователе и новом хосте).
- **А4-6.** `publicOrigin` без `CARREL_PUBLIC_URL` — `r.Host`. Анонимный
  POST `/forgot` с чужим `Host` отправляет владельцу подтверждённого адреса
  письмо со ссылкой на хост нападающего; щелчок отдаёт ему токен очистки, и
  он ставит учётке свой пароль. На carrel.mixfed.ru адрес задан — там не
  применимо. Рекомендация: письмо со ссылкой из анонимного запроса — только
  при заданном адресе; без него `/forgot` отвечает как без почты, а
  настройки почты администратора говорят задать «Public address».
- **А4-7.** Рекомендация: ведро на учётку для писем `/forgot` (как ведро
  входа, 5/мин, или реже) и один живой токен `/forgot` на учётку — новый
  сжигает прежний, как у консольной команды. Сейчас ведро только по
  адресу, а адресов IPv6 у нападающего много.
- **А4-8.** `mixfed.ru` не в списке публичных суффиксов: страница
  SelfPost или Wynd (или любой `*.mixfed.ru`) может поставить
  `carrel_sid` с `Domain=mixfed.ru; Path=/app/` — браузер шлёт её первой,
  и человек работает в учётке нападающего (подключит туда свой сервер с
  паролем). Рекомендация: имена `__Host-carrel_sid` и `__Host-carrel_csrf`
  при HTTPS и пустом `CARREL_BASE_PATH`; это меняет закрытую развилку
  «Сессии», поэтому — решение владельца.

### Проверено аудитом №4 — чисто

- Доверенный прокси: `clientIP` — самый правый недоверенный из
  `X-Forwarded-For` только от адреса из `CARREL_TRUSTED_PROXIES`;
  apache снимает присланный клиентом `X-Forwarded-For` до своего;
  контейнер слушает только `127.0.0.1`. `Secure` у кук — по TLS,
  доверенному `X-Forwarded-Proto` или https-адресу.
- Заголовки S-29.1 — у страниц, фрагментов, SSE, JSON, отказов и 404 мукса
  (`secureHeaders` вокруг всего мукса); файлы, вложения, файлы публикаций —
  песочница `downloadHeaders`; архивы копий — `octet-stream` с
  `attachment`. Мелочь без последствий: при непустом `CARREL_BASE_PATH`
  404 вне базового пути — от `StripPrefix`, без заголовков.
- Куки `carrel_sid`, `carrel_csrf`, столбцов, вида, плотности — HttpOnly,
  SameSite=Lax, Secure по тому же правилу, без `Domain` (о поддоменах —
  А4-8).
- Вёдра: вход, `/setup`, регистрация, приглашение, подтверждение адреса,
  `/forgot`, `/forgot/{token}` — на месте, ключ входа — нормализованный
  логин; голый `/` — редирект на свой `/app/`, не открытый.
- `readForm` и все четырнадцать вызовов: тело под потолком маршрута
  (`MaxBytesReader` до чтения), после А4-1 и А4-3 — без временных файлов;
  поля загрузок — 1 МиБ вместе (`uploadBody.keep`).
- Список, приходящий с панелью (`writePage`), и конец опроса с верхней
  полосой и рейлом (`search.go`): тело — та же модель того же запроса,
  задача — только своего сеанса (`sess.Task`); токен ставится
  `stampingRenderer.Fragment` и во вне-полосные части, в SSE —
  `stampView` каждой части. Чужих данных и POST без токена нет.
- `AddConnection` отмечает только коллекции этого подключения в своём
  блобе; пустой пароль у Connect и Test only — отказ у поля без запроса
  серверу, пароль в форму не возвращается.
- Disconnect (`RemoveConnection`): снимаются коллекции, отметки, места,
  связи дубликатов, исключения устройств, папки вложений и загрузок,
  источники копий, ссылки с затиранием конвертов; Edit перезапечатывает
  конверты ссылок новым паролем (о новом адресе — А4-5).
- Пул стража: ключ — отпечаток, каждый новый хост — через проверяющий
  дозвон, прокси нет; повтор записи — только по простоявшему соединению.
- `.well-known`: `Location` читается без перехода, понижение до HTTP —
  отказ; цель берётся после `current-user-principal` (S-6). Цель на другом
  хосте получает пароль — так устроены Google и другие (RFC 6764), закрытая
  развилка S-6.
- davloom «read only»: `PUT`, `DELETE`, `MOVE`, `COPY`, `PROPPATCH`,
  `MKCOL`, `MKCALENDAR`, `LOCK` — отказ 403 до отправки; `Destination` —
  только коллекция устройства на том же сервере.
- Счётчик открытий ссылки — только у совпавшей ссылки: растёт с числом
  ссылок, не с запросами.
- Перевязка `RELATED-TO` — только в отмеченных коллекциях сеанса.
- `cal.linkHref` и автоссылки — `http(s)` с хостом, `mailto`, `tel`;
  прочее — текст.
- Zip заметок: имена — подписи строк, выход из архива — отказ; член читается
  не дальше заявленной длины. Память не ограничена — исключение импорта
  (Р-73, S-29.4), не пересматривается.
- `returnPath`, оба `sheetBack`, Lock now — только путь своего адреса под
  `/app/` или `/admin/`, без хоста, `//` и `\`.
- Выбор расхождения `chosenSide`: только `mine` или `theirs`, иное —
  показанное.

## Не пересматривается

- **Ф-7.** Семафор на все вызовы KDF, порог 4, ожидание с контекстом.
- **Ф-8.** `store.User` не попадает во вью-модель и в `slog`.
- **Ф-14.** Переименование логина перезапечатывает обёртки и блоб в том же
  `Mutate`.
- **`Detail` журнала** — из словаря событий и открыто хранимых
  идентификаторов, **никогда** из поля запроса, тела записи или текста
  ошибки чужого сервера.
- **Ф2-1.** Регистрация переиспользует запись только как ту же незавершённую
  саморегистрацию; иначе `ErrLoginTaken`.
- **Ф2-4.** Всякий путь, ставящий пароль, сжигает все wipe-токены человека.
- **Ф2-6.** Промах входа стоит один Argon2 (`verifyDummy`).
- **Ф2-7.** `{account}` — подключение из блоба, открытого ключом сессии.
- **Ф2-9.** Маршрут секрета сверяется с `sess.UnlockUntil(now)`.
- **Ф2-11.** Адрес клиента — через `CARREL_TRUSTED_PROXIES`, самый правый
  недоверенный из `X-Forwarded-For`; на обоих слушателях.
- **Ф2-2, Ф2-5.** Всё, что растёт от чужих запросов, заводится с правилом
  вытеснения.
- **Депонирование (S-10.5).** Не задним числом; мастер не кэшируется; отказ
  удаляет копию в том же `Mutate`; только через лист S-10.7; `/forgot` для
  депонированного предлагает и «спросите администратора» (строка журнала
  `user.forgot.ask`, без мастер-пароля ничего не открывает); экраны wipe
  называют уничтожение, не «сброс»; очистка — кнопкой страницы (POST с
  CSRF), открытие ссылки из письма ничего не стирает.
- **Когда разрушение просит набрать имя** (решение владельца 29.09.2026):
  только когда человек не видит прямо, что стирается, и может промахнуться
  по чужому — администратор выбирает учётную запись из списка (сброс, S-10.6,
  набор логина). Кто пришёл по своей ссылке из письма, стирает свою — «не та»
  исключено, набор лишний; так же удаление карточки, которую человек видит.
- **Сброс администратором (S-10.6, s-admin-13).** Очистка S-10.4 целиком
  (`store.WipeAccount`) и временный пароль — в одном `Mutate`; обязательная
  смена при входе; пароль ни в состоянии, ни в журнале (`user.reset`);
  wipe-токены сгорают, сессии завершаются. Себя и отключённого — не
  сбрасывает. Депонированную — сбрасывает тоже (решение владельца
  28.09.2026): депонированная копия ключа уходит вместе с очисткой, путь без
  потерь — восстановление S-10.5.
- **Well-known (S-6).** Цель — только после `current-user-principal`, URI от
  корня origin.

## Принято как есть

- `end()` не обнуляет тела в кэше и черновики: содержимое, не ключи.
- Затирание ключа в `session.End` — best-effort, дамп памяти побеждает; копию
  `DataKey()` не класть в долгоживущую структуру.
- Поиск SID в `Manager.Get` не за постоянное время: 192 случайных бита.
- Исходящие порты не ограничены: DAV на своём порту законен.
- Argon2id t=3 / 64 MiB / p=1 — второй профиль RFC 9106.
- `/forgot` различает «есть что сделать» и «помочь нечем» (s-auth-6, s-auth-7):
  есть ли у логина или адреса подтверждённая почта — этого требует S-10.4.
  Логин, найденный по адресу, наружу не называется: страница говорит тем,
  что ввели.
- `GET /confirm-email/{token}` меняет состояние: ссылка из письма иначе не
  открывается. Токен одноразовый, ведро 30/мин.
- `Authenticate` глотает ошибку записи `LastLogin`: вход важнее отметки.
- Проверка установки ходит на адрес администратора мимо стража и с его
  кукой: цель — собственный адрес экземпляра.
- Архив «с этого компьютера» не ограничен по размеру: он уходит во временный
  файл, не в память.
- Карты вёдер davloom подметаются по истёкшим окнам.
- В `login.fail` нет адреса: журнал вечный, адрес — у живой сессии.
- Edit подключения с новым адресом и пустым паролем переносит сохранённый
  пароль на новый адрес (А4-5; решение владельца 25.11.2026: «Оставить, как
  есть»). Риск — открытый вход в чужих руках уносит пароль DAV мимо окна
  S-10.7. К обсуждению принятых рисков владелец просил вернуться позже
  (server.md, «Отложено владельцем»).
- **`mail.send` пишет адреса получателей** (S-26.2) — единственное
  исключение из правила «`Detail` не из поля запроса» (решение владельца
  28.09.2026). Письмо уходит с домена экземпляра через его релей, своего
  антиспама у Carrel нет, и за рассылку отвечает администратор: ему нужно
  видеть, кому пишут. Скрывать их в журнале незачем: получателя и так видно
  в панели релея домена экземпляра. Тема, текст и файлы в журнал не идут. Письмо со своего
  ящика (carrel-mailbox.md, M-7) журналирует только число получателей и
  вложений: за него отвечает не администратор Carrel.
