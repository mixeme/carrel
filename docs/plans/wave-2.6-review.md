# Проверка волны 2.6

Для модели, которая **проверяет** работу, а не делает её. План работы — [global-plan.md](global-plan.md) §7-бис; там же §2.6.F — инструкции исполнителю. Этот документ отвечает на другой вопрос: **что значит «сделано правильно» и как это установить**, не полагаясь ни на слово исполнителя, ни на собственное впечатление.

Документ временный и умирает вместе с планом.

---

## 0. Почему это отдельный документ

Волна 2.5 была сдана как закрытая дважды, и оба раза неверно. Первый раз — потому что тесты были зелёными, а тесты не проверяли вёрстку. Второй — потому что проверяющий посмотрел на экраны, и они выглядели правильно; выглядели правильно они из-за запасного правила по тегу, которое чинило заголовок и прятало то, что весь остальной перенос до десяти экранов не дошёл.

Отсюда три правила проверки, и они важнее любого чеклиста ниже.

1. **Зелёные тесты не доказывают ничего**, пока не показано, что тест умеет краснеть. Первое действие проверки — сломать проверяемое и увидеть падение.
2. **«Выглядит правильно» — не результат.** Значение либо совпадает с системой макета в числах, либо нет.
3. **Проверять по закрытому списку** — экранов, маршрутов, объявлений, — а не по списку того, что вспомнилось. Список должна давать машина.

## 1. Как поднять окружение

Приложение с данными и макеты рядом:

    CARREL_DATA_DIR=dev/data go run ./cmd/carrel
    cd docs/visual && python -m http.server 8081

Приложение — `127.0.0.1:8080`, макеты — `127.0.0.1:8081/carrel-ui-mockups.html`. Учётные данные администратора и тестовых DAV-серверов — в `dev/credentials.txt`, вне git. Календарь `cal 2` содержит 142 записи реального экспорта, `book 1` — 29 контактов.

**Проверять на пустом экземпляре бессмысленно:** половина расхождений видна только на данных, и обе несостоявшиеся сдачи волны 2.5 это подтвердили.

## 2. Что проверяется само

    go build ./... && go vet ./... && gofmt -l . && go test ./...

`gofmt -l .` обязан молчать. В `go test` входят гейты, которые и есть определение «правильно» для формы:

| Тест | Что держит |
|---|---|
| `TestStylesheetKeepsTheTypeScale` | ни одного кегля вне системы макета; ни одного `rem` — система в пикселях |
| `TestStylesheetKeepsTheTwoFamilies` | ни одного семейства мимо трёх токенов |
| `TestEveryPageObeysTheMarkupRules` | на **каждом** маршруте, выведенном разбором `routes.go`: нет inline-стилей, нет inline-скриптов, нет ссылок на чужой хост |
| `TestTemplatesCarryNothingInline` | то же в исходниках шаблонов |
| `TestBaseLoadsTheStreamExtension` | расширение SSE подключено и после htmx; в `carrel.js` есть запасной опрос |
| `TestDuplicatesDoNotPollFileCollections` | §15 не опрашивает файловые коллекции |

**Первым делом — убедиться, что гейты кусаются.** Не прочитать тест, а сломать проверяемое:

- дописать в любое правило `carrel.css` строку `font-size: 14px;` — обязан упасть `TestStylesheetKeepsTheTypeScale`;
- заменить в правиле семейство на `Georgia, serif` — обязан упасть `TestStylesheetKeepsTheTwoFamilies`;
- вернуть `style="padding:4px"` в любой шаблон — обязаны упасть **оба** теста разметки, шаблонный и маршрутный.

После каждой проверки — `git checkout -- <файл>`. Если хоть один гейт промолчал, это дефект проверки, и он важнее любого дефекта в работе.

## 3. Что тестами не проверяется

### 3.1 Совпадение с кадром — числами, не взглядом

Снять вычисленные стили с макета и с приложения и сравнить посимвольно. Проба, которой снимались все числа этой волны:

    const probe = (sel, root) => {
      const el = (root || document).querySelector(sel);
      if (!el) return sel + ' | НЕТ';
      const c = getComputedStyle(el), px = v => v.replace('px', '');
      return [sel, c.fontFamily.split(',')[0],
        px(c.fontSize) + '/' + c.fontWeight + '/' + px(c.lineHeight),
        c.letterSpacing, c.textTransform, c.color, c.backgroundColor,
        [c.paddingTop, c.paddingRight, c.paddingBottom, c.paddingLeft].map(px).join(' '),
        px(c.height)].join(' | ');
    };

Кадр выбирается по номеру из таблицы §4: `document.querySelectorAll('.mock')[9]`, дальше `probe('.m-head', кадр)`.

**Три ловушки метода**, каждая уже давала ложный результат:

- **Кадр макета узкий** — рабочая колонка около 535 px, и внутри срабатывает `@container (max-width:620px)`: отступы строк 12 вместо 20, колонок меньше. Это не расхождение. Сверять правила либо сузить окно приложения до ширины кадра.
- **Переходы не проигрываются**, когда панель браузера скрыта: класс поставлен, `transform` прежний, шторка кажется сломанной. Помогает `el.getAnimations().forEach(a => a.finish())` перед замером.
- **Значение не то при верном классе** — значит правило перебито, и надо найти перебивающее, а не дописывать `!important`. Обойти `document.styleSheets[0].cssRules`, собрать все правила, для которых `el.matches(r.selectorText)`, и посмотреть последнее: побеждает оно. Так были найдены все четыре расхождения типографики этой волны.

### 3.2 Контрол должен работать, а не изображать

Второе условие приёмки и та часть, которую нельзя проверить чтением кода.

| Контрол | Проверка | Что считается провалом |
|---|---|---|
| Фильтр в панели | ввести подстроку на `/app/contacts` | список не сузился; **или** набранное стёрлось, когда пришла очередная порция опроса, — значит панель положили внутрь `#find-panel`, который заменяется целиком |
| Сортировка | переключить на заметках | порядок не изменился; выбор не пережил перезагрузку |
| `Open / Done / All` | переключить на задачах | числа не сходятся с содержимым списка |
| `Compact rows` | переключить | высота строк не изменилась; настройка разошлась с той, что в Appearance |
| `Test` у подключения | нажать у сохранённого аккаунта | нет следа шагов (well-known, principal, home-set); **пароль виден в выводе при `CARREL_LOG_LEVEL=debug`** — это отказ, а не замечание |
| `Export CSV` | скачать журнал | файл не открывается; содержимое не то, что на экране |
| `⋯` | открыть на каждом экране | пункт есть, действие не делает ничего |

### 3.3 Разрушительное и секретное — диф глазами

`development.md` требует отдельного прохода для крипто, исходящих соединений и разрушительных операций. В волне под это попадают шаги **2.6.C1–C4**. Проверяется построчно:

- пароль берётся через `sess.DEK()` и **никуда не пишется** — ни в лог, ни в шаблон, ни в ответ;
- исходящий запрос идёт через `s.Guard` (SSRF, §24.2) и через существующий лимитер;
- `Edit` подключения **не меняет `account_id`** — к нему привязаны выбор источников и решения о дубликатах;
- удаление требует подтверждения набором имени и пишет в аудит.

## 5. Отчёт

Не «проверил, всё хорошо». По каждому пункту — что запущено и что получено.

1. **Гейты кусаются:** какой дефект вносился, какой тест упал.
2. `go test ./...`, `go vet ./...`, `gofmt -l .` — вывод.
3. **Сверка с кадрами:** какие пары сверены, какие числа разошлись. Если не разошлись — так и написать, перечислив пары.
4. **Живая проверка контролов:** что нажато, что произошло.
5. **Диф по 2.6.C1–C4** — прочитан или нет.
6. **Чего проверить не удалось и почему.** Самый ценный пункт: обе несостоявшиеся сдачи волны 2.5 состояли ровно из того, что было не проверено и объявлено проверенным.

**Проверка не обязана заканчиваться словом «принято».** «Форма сошлась, поведение на живых данных не проверено» — законный результат, и он полезнее ложного «принято».
