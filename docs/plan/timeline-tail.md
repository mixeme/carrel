# Хвост: хронология человека

Найдено ревью перед S-30 ([review-server.md](review-server.md), Р-11).

`GET /app/contacts/{account}/{col}/{uid}/timeline` стоит в C-5.4, у него есть
вью-модель `ContactTimelinePage` (C-6.5) и кадр `s-contacts-7`. На сервере это
заглушка: `web.ownedRecordStub` проверяет владение и отвечает 404. У карточки
контакта не заполнены врезка `Timeline` и действие `More` («Open the
timeline»). Поле `Books` заполняется только связанными дубликатами.

В спеке сервера этой функции нет вовсе: ни раздела, ни требований к опросу. По
кадру это главный ответ на «зачем четыре раздела вместе»: встречи с человеком,
его задачи, заметки о нём и файлы, приложенные к ним, с нескольких серверов в
одной ленте.

Порядок: сначала раздел спеки (решения ниже согласовать с владельцем), потом
код.

## Что показывает кадр

- **Рейл «Where to look»** — календарные коллекции с числом совпадений, у
  отказавшей — причина и Retry (S-21).
- **Шапка**: карточка человека, «in 2 books», кнопки Write a note, New event,
  New task, Print.
- **Полоса**: диапазон (From → Show), сегменты All · Events · Tasks · Notes ·
  Files со счётом, порядок newest first.
- **Строка опроса**: «Polled 4 of 5 calendars · matched by <адреса> and the
  name · <источник> unavailable».
- **Строки** по месяцам: дата, заголовок, «почему совпало» (обязательная
  колонка), род, источник.
- **Подвал**: «Nothing was looked for before January 2026. Widen the range if
  you need it.»
- **Панель**: карточка как контекст экрана.

## Развилки для владельца

1. **Чем опрашивать.** Веер S-15 по отмеченным календарным коллекциям:
   - `ATTENDEE` и `ORGANIZER` с `mailto:` каждого адреса карточки — точное
     совпадение;
   - text-match по имени в `SUMMARY` и `DESCRIPTION` — догадка.
   
   Колонка «почему» говорит, чему верить: «attendee · accepted», «organiser»,
   «mentioned in the title», «mentioned in the text». Предложение: так, одним
   REPORT на свойство, как поиск (CalDAV prop-filter — allof).
2. **Файлы** — только вложения уже найденных записей (`ATTACH`), без обхода
   хранилищ. Так написано в кадре, и это не противоречит S-15.2.
3. **Окно по умолчанию** — с начала года, как в кадре, или год назад.
   Предложение: 12 месяцев назад до 3 месяцев вперёд; «Widen the range» —
   поле From.
4. **Врезка на карточке** (`ContactPage.Timeline`) — только из того, что уже
   лежит в сессии (выдача прошлой хронологии этого человека), без опроса при
   открытии карточки. Нет в памяти — врезки нет, есть только `More`. Иначе
   каждое открытие карточки становится веером.
5. **Write a note / New event / New task** — быстрый лист (U-6.16) с
   подставленным участником (`ATTENDEE` у события) и связью (`RELATED-TO` у
   заметки и задачи — на что?). У заметки о человеке связи с карточкой нет:
   RELATED-TO между VJOURNAL и vCard не определён. Предложение: заметка
   получает имя в заголовке и адрес в тексте, без связи.

## Решения владельца 19.09.2026

Хронология — это поиск (S-15), только по одному человеку: опрашиваются все
источники, а не то, что уже загружено.

1. **Чем опрашивать:** адреса почты карточки (`ATTENDEE`, `ORGANIZER` с
   `mailto:`) и `RELATED-TO` на UID карточки. Имени в тексте не ищем.
2. **Файлы:** по имени файла, в хранилищах, как поиск файлов S-15.
3. **Окно:** от 12 месяцев назад до 3 месяцев вперёд — в календаре бывают
   и предстоящие встречи с человеком. «Widen the range» отодвигает начало
   ещё на 3 месяца назад за раз; конец остаётся на 3 месяцах вперёд. Подвал
   говорит, с какого дня искали («Nothing was looked for before …»).
4. **Врезка на карточке** показывает то, что человек уже открывал в этой
   сессии. Открытие карточки хронологию не собирает; собирается она только
   при явном открытии (`More`, `/timeline`).
5. **Write a note / New task** пишут человека в `RELATED-TO` (UID карточки).
   RFC 5545 не определяет связь VJOURNAL и VTODO с vCard, но `RELATED-TO` —
   это UID, и связь читается Carrel в обе стороны (S-11).
