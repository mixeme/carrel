# Ревью сервера перед S-30

Пункт «**Opus.** Ревью сервера перед S-30» из [reviews.md](reviews.md), начат
19.09.2026. Объём шире пункта: весь код `carrel/server`, соответствие
[carrel-server.md](../spec/carrel-server.md) и серверной стороне
[carrel-common.md](../spec/carrel-common.md), функции и поведение по кадрам
[carrel-ui-mockups.html](../visual/carrel-ui-mockups.html). Клиент (`U`) и
настольное приложение не входят. Безопасность — отдельное ревью: найденное по
дороге записано с пометкой **→ безопасность** и не чинится.

Находки чинит рецензент (C-16: сначала красный тест, потом правка), каждая —
свой коммит с записью в [CHANGELOG](../../carrel/server/CHANGELOG.md). Крупный
хвост и продуктовое решение уходят отдельным планом, а не строкой здесь.

Степень: **блокер** — теряет данные или роняет процесс; **серьёзно** —
расходится со спекой в поведении, которое человек увидит; **мелочь** — всё
прочее.

## Находки

| № | Степень | Где | Что | Статус |
|---|---|---|---|---|
| Р-1 | блокер | `provider/card`, `provider/cal`, `model` | Любая правка карточки переписывала её целиком через go-vcard: терялись группы Apple (`item1.`), значения `TYPE` после первого, запятые-разделители `CATEGORIES`, кавычки параметров; у события — второй адрес `DELEGATED-TO`. Проверка потерь этого не видела (S-7, C-15) | `v0.0.124`, SV-32 |
| Р-2 | блокер | `dav`, `provider/cal` | go-ical паникует на кривой строке; паника в веере — конец процесса и всех сессий. Одна нечитаемая запись делала весь календарь недоступным (S-21) | `v0.0.124`, SV-33 |
| Р-3 | серьёзно | `fanout`, `web` (фото, копия) | Горутины без `recover`: паника любого разбора в источнике веера, миниатюре или прогоне копии роняла процесс. Источник теперь падает сам, остальные отвечают | `v0.0.125` |
| Р-4 | серьёзно | C-8, `web` | Служебные значения форм (`_csrf`, `etag`, `readat`, `op`, `action`, `id`) шли строками `text` без подписи: в C-8 не было скрытого вида, клиент не отличил бы их от поля. | Р-5 | серьёзно | `dav` (страж) | Загрузка файла потоком уходила в соединение из пула; если сервер только что его закрыл, файл терялся: повторить поток нечем. Поймано полным живым прогоном (SFTPGo, вложение S-20) | `v0.0.127`, SV-14 |

Подпись кнопки — данные сервера (C-3.1) | `v0.0.129` |
