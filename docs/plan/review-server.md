# Ревью сервера перед S-30

Пункт «**Opus.** Ревью сервера перед S-30» из [reviews.md](reviews.md), начат
19.09.2026. Объём шире пункта: весь код `carrel/server`, соответствие
[carrel-server.md](../spec/carrel-server.md) и серверной стороне
[carrel-common.md](../spec/carrel-common.md), функции и поведение по кадрам
[carrel-ui-mockups.html](../visual/carrel-ui-mockups.html). Клиент (`U`) и
настольное приложение не входят. Безопасность — отдельное ревью: найденное по
дороге записано с пометкой **→ безопасность** и не чинится.

Находки чинит рецензент (C-16: сначала красный тест, потом правка), каждая —
свой коммит с записью в [CHANGELOG](../../carrel/server/CHANGELOG.md). Крупный
хвост и продуктовое решение уходят отдельным планом, а не строкой здесь.

Степень: **блокер** — теряет данные или роняет процесс; **серьёзно** —
расходится со спекой в поведении, которое человек увидит; **мелочь** — всё
прочее.

## Итог

**Сервер к закрытию S-30 не готов**. Главная причина — Р-13: критерий C-14.2
«на каждый обработчик есть проверка „вью-модель равна фикстуре“» не выполнен.
Кроме того, Р-9, Р-10 и Р-11 — функции из C-5 и кадров, без которых продукт
заметно неполон:

- отключить или поправить подключение;
- править дату рождения, адрес, категории, повторение;
- хронология человека.

Всё, что теряло данные или роняло процесс, исправлено: Р-1, Р-2, Р-3, Р-5, Р-14,
Р-15.

Что держится хорошо и замечаний не дало:

- слои S-1: `web` не протекает вниз, провайдеры не знают про запрос;
- предусловия записи (S-8);
- слияние дубликатов: запись, перечитывание, удаление по одному, остановка на
  первом отказе;
- перенос файлов между хранилищами: исходник удаляется после полной копии;
- поиск и веер: состояния C-8.1, частичные результаты, повтор одного источника;
- обходы особенностей серверов в [servers.md](../servers.md);
- ворота и живой набор.

## Как проверялось

- Спека сервера целиком; C-5, C-6, C-8, C-12, C-14 общей части; план
  [server.md](server.md).
- Код:
  - построчно — `model`, провайдеры `card` и `cal`, чтение отчётов в `dav`,
    страж, веер;
  - выборочно — `web` (формы, записи, файлы, дубликаты, экспорт, импорт,
    публикация), `session`.
- Живой экземпляр на Windows с подключёнными Baikal, Nextcloud и SFTPGo:
  экраны сняты JSON и сверены с текстом каждого из 88 кадров с адресом.
- Ворота `scripts/gates.sh` перед каждым коммитом. Полный живой набор с
  Windows: 45 зелёных. Три падения — сеть (таймаут PUT на SFTPGo, EOF у
  Nextcloud, письмо не дошло за 8 минут); повторно по отдельности зелёные, а
  одно из них вскрыло Р-5. Новый живой тест `TestBaikalBigBook`. Linux-ворота
  (Radicale, Docker, F-10) — на коммите `a9f6287`.

## Не проверялось

- **Безопасность** — отдельное ревью. По дороге замечено: вход, удачный и
  неудачный, не пишется в журнал действий
  ([views-tail.md](views-tail.md)).
- davloom, почта, копия и восстановление — только через их тесты и живой
  набор, без построчного чтения.
- Узкий экран, тема, печать — сторона клиента.
