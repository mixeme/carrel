# Узкий рейл — выдвижная панель

**Composer.** Хвост сборки экранов через оболочку: на 375 px колонка рейла
схлопывается (`width: 0`), а `tc-nav` / `tc-rail` уезжают за край
(`translateX(-100%)`). Кнопки открыть панель нет: `data-tc-rail-toggle` в
`tc.js` есть, в разметке экранов и в `Top` — нет. Спека L-4.1: в узкой
раскладке рейл — выдвижная панель на весь экран, закрывается кнопкой
применения.

Правило прежнее: один коммит на пункт, сначала проверка, которая краснеет на
текущем коде, потом правка.

---

## Почему это осталось

План оболочки закрыл пустые колонки, сборку экранов через виджеты и вылет
`tc-bar` / `tc-crumbs` на 375 px. Рейл спрятали, чтобы он не занимал 264 px
и не вылезал из вьюпорта. Выдвинуть его обратно нечем.

Старые решения оболочки — в [reviews.md](reviews.md), «Оболочка Typecase».
Узкий хром — кадр 10 (`#m-phone`), не 7.4: 7.4 — содержимое колонки заметок.

---

## Закрытые развилки

Не пересматривать. Нет в списке — спека L-4.1 (`tc-shell`, `tc-rail`, `tc-nav`),
U-9, кадр 10.

**Механизм — `tc-rail--drawer`.** Класс и `is-open` уже есть: `inset: 0`, на весь
экран. Второй путь — `.tc-shell--narrow .tc-shell__rail > .tc-nav / .tc-rail`
с `position: fixed` и `translateX(-100%)` — убрать. Колонка `.tc-shell__rail` на
узкой ширине по-прежнему `width: 0`, чтобы не занимать 264 px. Экраны не
передают `Rail.Layout` / `Drawer`: `tc-rail--drawer` ставит `tc.js` вместе с
`tc-shell--narrow`. Клетка `tc-rail / drawer` — тот же класс. Без сценариев
класс не ставится, рейл остаётся в потоке (L-4.1, U-8).

**Кнопка открытия — в `tc-top`, не внутри рейла.** Сейчас `tc.js` ищет
`[data-tc-rail-toggle]` внутри `[data-tc-rail]` — оттуда её не нажать, когда
панель за краем. Кнопка — первый узел `tc-top`, `tc-btn` с подписью
`labels.Sources`, атрибут `data-tc-rail-toggle`. Видна только при
`.tc-shell--narrow` и непустой колонке рейла. Не поле `Top`. `Shell.Render`
выпускает её, когда есть `Nav` или `Rail`. Не кнопка только со значком
(L-4.4): кадр 10 рисует гамбургер — у библиотеки подпись. Знак `Brand` не
подменять заголовком «Sources».

**Apply — хром панели, не действие `RailFoot`.** На кадрах подвал рейла —
«New notebook» / подключение, не Apply. Кнопка `labels.Apply` с
`data-tc-rail-apply` живёт в `tc-top`, видна когда рейл `.is-open`. Нажатие,
`Esc` и повторный toggle закрывают панель; фокус возвращается на toggle
(L-4.1). `dblclick` по чипам не трогать и не считать контролом.

**В панели только `tc-rail`.** `tc-nav` на узкой ширине — состояние `bottom`
(L-4.1, U-9, кадр 10): `tc.js` ставит `tc-nav--bottom`, навигацию в drawer не
прятать. Разделы всегда видны, в меню не сворачиваются. DOM не менять:
`Shell.Nav` по-прежнему в колонке рейла, пятой зоны нет. Открытая панель на весь
экран накрывает нижнюю полосу. `Nav.Layout` на экранах не ставить.

**Каталог `tc-shell / narrow`** — тот же toggle, тот же drawer, с `Nav`. Сейчас
в клетке навигации нет — без неё клетку нельзя сверить с экранами.

## Задача

### 1. Открыть и закрыть рейл в узкой раскладке

Спека: ниже порога рейл — выдвижная панель, не пропавший столбец. Сейчас
`tc-shell--narrow` прячет колонку без контрола. `dblclick` по чипам на
телефоне недоступен, и чипов может не быть.

- [ ] В узкой раскладке в `tc-top` есть `data-tc-rail-toggle` (`labels.Sources`)
- [ ] Открытый рейл — `tc-rail--drawer.is-open` на весь экран; закрывается
      `data-tc-rail-apply` (`labels.Apply`), `Esc`, повторным toggle; фокус
      возвращается на toggle
- [ ] Ворота: браузерная проверка на 375 px открывает рейл и видит `tc-rail` во
      вьюпорте; закрытый рейл не во вьюпорте, не даёт `OutOfBounds` и не даёт
      горизонтальной прокрутки; `tc-nav` при закрытой панели виден как
      `tc-nav--bottom`
- [ ] Узкая раскладка по-прежнему в `tc.js`, не полем экрана

### 2. Не плодить второй выдвижной механизм

Уже есть `tc-rail--drawer` и `data-tc-rail-toggle`. Узкая оболочка рисует
другой `position: fixed` на детях колонки. Остаётся первый.

- [ ] Один способ выдвинуть рейл: `tc-rail--drawer`. Правила
      `.tc-shell--narrow .tc-shell__rail > .tc-nav / .tc-rail` убраны.
      Нижняя навигация — состояние `tc-nav`, не второй drawer
- [ ] Каталог `tc-shell` / `narrow` показывает тот же механизм, что экраны:
      toggle в `tc-top`, `Nav` снизу, рейл — drawer

## Что не чинить

- Пустой `Rail` / `Side` не выпускает колонку — это не «спрятать рейл».
- `notes-edit` без колонок — нулевое значение, не узкая раскладка.
- `Overlay.Body` и `Dialog` не переводить на `[]Node` в этом плане.
- Боковая панель на узкой ширине уже накрывает вьюпорт; «меню строки вместо
  панели» (U-9) — не этот план.
