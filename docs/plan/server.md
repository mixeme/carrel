# План: сервер

Спека: [carrel-server.md](../spec/carrel-server.md), шов: [carrel-common.md](../spec/carrel-common.md). Раскладка и пины: [architecture.md](architecture.md). Ревью: [reviews.md](reviews.md).

Модуль — папка `carrel/server/`, `module carrel.dev/carrel/server`. Не корень репозитория и не корневой `server/`. Typecase не импортирует.

Исполнитель — Composer, кроме чекбоксов с **Opus**. Аудиты Fable — в [reviews.md](reviews.md), после соответствующих слоёв, не вместо них.

---

## Что нельзя

- Шаблоны, CSS, `tc-*`, имена виджетов.
- `import` пакета Typecase из любого пакета этого модуля, включая `cmd`, **в рамках этого плана**. (Когда появится клиент, импорт будет только в `cmd/carrel`, не в `internal`.)
- Пересборка объекта из полей формы; экспортируемое «сырое» тело.
- Запись без предусловия (S-8).
- `map[string]any` во вью-моделях.
- SQLite, Redis, соседние процессы.
- Буферизовать файл целиком в `[]byte` на пути скачивания.
- Ответ 500 на молчание чужого DAV-сервера.
- Различимый ответ «нет / чужое / отозвано / истекло» для секретов.

Слои — как S-1. Обработчики HTTP — после модели. До них пакет тестируется своими тестами.

### Переменные C-12, которые разбираются и не применяются

- [x] `CacheCollectionTTL` действует: коллекция старше срока перечитывается, а не отдаётся из кэша вечно. Срок — на списки коллекций и карты версий; тела и миниатюры живут по версии объекта, им TTL не нужен
- [x] `LogLevel` действует: `slog` настраивается уровнем из C-12. Проверить на `debug`, что в журнал не попадают пароли, токены и тела записей (S-29) — это же требование в разделе поставки

### Кэш сессии

- [x] Одно правило вытеснения вместо двух. Внутри сессии вытесняется по `at`, как уже делает `evictProcessWide`; либо `c.order` честно перестаёт называться LRU. Сейчас поле названо LRU, а является порядком вставки: `get` двигает отметку времени, но не позицию

### Красные ворота не по вине сервера

`python docs/spec/check.py` возвращает 1, и это последний шаг workflow
`carrel-server.yml`. Триггер включает `carrel/server/**`, поэтому **любой
серверный коммит ложится в красный CI** — при том, что сам сервер зелёный:
`gofmt`, `vet`, статическая сборка и `-race` проходят и стоят до спек-проверки.

Классы `tc-*` серверу запрещены, в `carrel/server` их нет ни одного. Правка
целиком в спеке, но чинит её тот, кому она мешает.

Причина — хвост переименования `tc-row--file` → `tc-row--meta`. Само
переименование сделано и записано ([typecase.md](typecase.md), CHANGELOG
Typecase); спеку за ним не дотянули. Решения принимать не надо, обе правки
механические.

- [ ] Проверка 3 (виджеты U-6 объявлены в L-4). В [carrel-client.md](../spec/carrel-client.md) пять раз `tc-row--file` → `tc-row--meta`: строки 416, 431, 488, 525, 535. `L-4` уже объявляет `tc-row--meta`
- [ ] Проверка 3b (классы кадров разобраны картой U-5.4). В макетах живёт `.m-row--file`, а в карте U-5.4 строки для него нет вовсе — класс не переименовывали, его просто не внесли. Добавить **одну** строку после `m-row--note` (карта — около строки 238): `| \`m-row--file\` | \`tc-row--meta\` | Значок типа, имя, размер, время |`
- [ ] `check.py` возвращает 0, проверки 3 и 3b зелёные

Чего **не** делать:

- Не переименовывать `m-row--file` в [carrel-ui-mockups.html](../visual/carrel-ui-mockups.html) — там 11 мест, и они правильные. `m-*` — имена кадров, карта U-5.4 их и переводит. Правится карта, не макеты
- Не трогать закрытые `[x]` в [typecase.md](typecase.md): они описывают состоявшееся переименование, это история, а не задача
- Красную проверку сперва увидеть красной (C-16). Здесь это даром: она красная уже сейчас

### Объём CI — закрытая развилка

Workflow оставляем и **не растим**. Он существует не ради автоматизации: две
проверки периметра на машине разработки физически не выполняются — `-race`
требует cgo, а тест прав `server.key` (Ф-10) на Windows `t.Skip` навсегда. CI
на `ubuntu-latest` — единственный Linux, который есть у проекта, и единственное
место, где «ворота зелёные» из C-16 проверяются машиной, а не утверждаются в
сообщении коммита.

Не заводить: матрицы ОС и версий Go, пороги покрытия, значки в README,
отдельные задания на линтеры. Появится нужда — обсуждать отдельно, не «заодно».
