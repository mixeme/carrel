## Вопросы к кадрам (кандидаты в задачи Typecase)

Не повторяют задачи 133, 136, 159 (закрыты), 88, 90 (бросок и «требует
сценариев»), 109, 174.

- **В1. Шаг 1 событий и задач.** `s-io-3` нарисован для контактов; подпись
  говорит «меняются слово в заголовке и принимаемое расширение». Нет:
  подписи поля файла («iCalendar file»?), строки под ним (сервер шлёт
  придуманное исполнителем: «iCalendar 2.0. One file holds any number of
  events; tasks and notes in it are named and left out. An address book
  takes ‹.vcf› here instead.», `import.go:392`), подсказки Into шага 1 для
  календаря и списка задач. Нужны слова (или кадры).
- **В2. Берут ли заметки `.ics`.** `s-io-4`: `accept=".md,.zip"`, подпись
  «Markdown or a zip of them»; сервер принимает и `.ics` (VJOURNAL,
  `importFormats`, `import.go:186`), заметка отдаёт себя `.ics` (задача 174),
  а предпросмотр календаря отправляет VJOURNAL «import it into a notebook».
  Если `.ics` — источник заметок, нужны подпись, `accept` и строка под
  полем; если нет — куда вести VJOURNAL.
- **В3. Набор файлов заметок.** Подпись `s-io-1` — «больше одного файла
  разом берут только заметки»; поле `s-io-4` без `multiple`, шапка
  предпросмотра `s-io-8` — один файл («заметки-2026.zip · 1.2 MB · 64
  files»). Как выглядит шаг 1 с несколькими `.md` (Browse с выбором
  нескольких?) и подзаголовок предпросмотра набора («3 files · 12 KB»?).
- **В4. Пустое «Into» входа из сведённого вида.** Подпись `s-io-1`: шаг 1 с
  уже вписанным файлом и пустым Into. Кадра нет: что пишет пустое поле, как
  стоит выключенная Preview file и её причина («Choose under «Into» where
  the records go.», `import.go:485`), где имя взятого файла.
- **В5. Накладки отказа броска.** Чужое расширение — слова есть только в
  подписи `s-io-1` («Contacts take ‹.vcf› — the calendar and the list of
  tasks take this one»); больше одного файла не у заметок — «накладка
  просит бросать по одному», слов нет. Нужны кадры или слова обеих.
- **В6. Что считать ошибкой.** `s-io-6`, `-14`: событие с DTSTART без DTEND
  и DURATION — отказ «cannot tell how long it lasts»; RFC 5545 §3.6.1 такое
  событие допускает (DATE — один день, DATE-TIME — миг), сервер его пишет.
  `s-io-7`: задача без SUMMARY и DESCRIPTION — отказ «nothing to name it
  by»; безымянные карточку и событие кадры отказом не рисуют (в `s-io-5`,
  `-6` отказ — по другой причине), сервер пишет их «Unnamed contact» /
  «Untitled event». Роды равны: отказ безымянной записи — у всех родов или ни
  у кого? И остаётся ли отказ без DTEND вопреки RFC?
- **В7. Одна ошибка — два текста.** Предпросмотр `s-io-5`: «vCard 2.1
  quoted-printable: cannot decode line 12», отчёт `s-io-9`: «line 12: cannot
  decode quoted-printable»; `s-io-6`: «…: cannot tell how long it lasts»,
  `s-io-14`: «— (no SUMMARY): DTSTART without DTEND or DURATION». Строка
  отчёта — «название: причина», а у карточки без имени — с номера строки?
  Нужно правило: одна фраза на отказ или короткая для отчёта, и чем
  начинается строка без названия.
