# Хвост: управление подключением

Найдено ревью перед S-30 ([review-server.md](review-server.md), Р-9). Подключение
можно завести, но **нельзя ни отключить, ни поправить, ни проверить заново**. У
`user.Service` есть `AddConnection` и `ApplyRediscovery`, а `RemoveConnection` и
`UpdateConnection` нет. Карточка на `/app/settings/connections` отдаёт только
«Look for changes» и «New collection».

Что обещано:

- C-6 `ConnectionCard.Actions`: «Test · Test again · Edit · New collection · Delete».
- Кадр `s-profile-1`: «Show password | Test | Edit | Disconnect».
- `ConnectionCard.Trace` — «след последней проверки», у отказавшего аккаунта
  прямо на карточке.
- Кадр `s-profile-2`: форма «Connect account» с полями Label, Server URL,
  Username, Password и кнопками Connect, Test only, Cancel.

Что это значит для человека:

- Пароль сменили на сервере — подключение умерло навсегда.
- Сервер переехал на другой адрес — то же.
- Подключение, заведённое по ошибке, остаётся в рейле, в поиске и в каждом
  опросе до конца жизни учётной записи.

Исполнитель — Composer. Шаги по порядку, каждый — свой коммит, тестом вперёд
(C-16).

## Закрытые развилки

- **Лист Disconnect — брат листа удаления коллекции** (решение владельца
  19.09.2026): та же сборка «что именно уйдёт», но без «скачать сначала» и
  без архива — на сервере ничего не удаляется, спасать нечего. Подтверждения
  набором имени тоже нет по той же причине.

- **Слово — Disconnect, не Delete** (кадр `s-profile-1`). Подключение уходит из
  Carrel, на сервере не трогается ничего. «Delete on the server…» остаётся у
  коллекции. C-6 в комментарии `ConnectionCard.Actions` правится тем же коммитом:
  `Delete` → `Disconnect`.
- **`{account}` не меняется при правке** (C-4.1: «переживает смену адреса и
  пароля»). Edit — тот же `a-…`, новые адрес, логин, пароль, отпечаток.
- **Edit — это новое обнаружение.** Сохранить без успешного `discover.Run`
  нельзя. Каталог после него сверяется, как при повторном обнаружении (S-6.1):
  разница — предложением, не подменой. Коллекции, которые остались по тем же
  путям, сохраняют галочки и связи.
- **Test — только чтение**, `discover.Run` с сохранёнными учётными данными,
  без записи в каталог. Результат — `ConnectionCard.Trace` в кэше сессии, не в
  блобе: след принадлежит сеансу, как выдача поиска.
- **Disconnect — одно действие с подтверждением** на листе. Лист перечисляет,
  что уйдёт вместе с подключением (список ниже), и не делает вид, что это
  мелочь.

## Что снимает Disconnect

Одним `editBlob`, одной строкой журнала `connection.remove` с числами, без
адресов. Под ключом данных:

- `Connections` — сама запись.
- `Collections` его `AccountID`.
- `Selected`, `LastUsed`.
- `Duplicates.Linked`: участники этого подключения; группа из одного
  распускается (S-16).
- `Duplicates.Ignored` не трогается: это подписи групп, а не адреса, и
  группа без участников этого подключения — уже другая группа.
- `DeviceExcluded`.
- `BackupJobs`: источники этого подключения. Задание, у которого назначение —
  это подключение, остаётся и помечается «назначения нет». Задание не удаляется
  молча.
- `Attachments` и `UploadTo`, если указывают сюда: становятся `nil`, и
  вложения снова спрашивают папку.
- `Links`: записи ссылок этого подключения.

В `state.enc`:

- `PublishedLink` этого `AccountID` отзываются. Конверт с паролем удаляется
  вместе со ссылкой (S-25: «отозвали последнюю ссылку подключения — конверт
  удалить»).
- `ProxyDevice.ScopeCols` этого подключения вычищаются.
- Кэш сессии по `conn.ID` — `InvalidateCollectionList` и индекс.
- Идущие веерные задачи с источниками этого подключения доживают. Их
  результаты при показе отбрасываются по отсутствию подключения в каталоге —
  это уже так.

Лист подтверждения (`ConnectionRemoveSheet` — новая вью-модель: C-5.7 строка
`/app/settings/connections?op=disconnect` GET, POST — **правка контракта,
согласовать с владельцем**; либо лист на существующем адресе с `op`, как у
подписок) перечисляет:

- сколько коллекций уйдёт из рейла;
- какие публичные ссылки перестанут открываться;
- какие задания копии потеряют источник или назначение;
- какие устройства davloom перестанут видеть коллекции.
