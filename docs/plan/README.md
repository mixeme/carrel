# Планы реализации

Спеки в [docs/spec/](../spec/) описывают **что должно быть**. Здесь — **как это кладётся в репозиторий и в каком порядке делается**, с закрытыми развилками, чтобы работу вёл Composer.

Клиент (`U`) и настольное приложение (`D`) в эти файлы не входят.

| Файл | О чём |
|---|---|
| [architecture.md](architecture.md) | Модули (`typecase/`, `carrel/server/`), зависимости на 04.09.2026, закрытые развилки, сроки и лимиты |
| [server.md](server.md) | План серверной половины (`S`) |
| [reviews.md](reviews.md) | Opus-ревью и аудиты Fable |
| [typecase-compose.md](typecase-compose.md) | Дыры API, из-за которых экраны макета собираются в обход виджетов (`Э-`), хвост L-4.4, закрытые развилки сборки |
| [users-tail.md](users-tail.md) | Хвост аудита Fable №2: учётки, секреты, депонирование, панель — что осталось после коммита аудита |

**Исполнитель по умолчанию — Composer.** Если шаг делает другая модель, это написано в чекбоксе: `Opus`, `Fable`. Composer эти шаги не выполняет.

Чекбоксы — прогресс работ. Их отмечают в этих файлах по мере коммитов. В файлах спеки пометок «готово» нет (C-16).
