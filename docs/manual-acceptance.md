# Ручная приёмка v1

Единый чеклист для всего объёма v1 (этапы 1–7 закрыты в коде, целевой тег v0.7.0 / v1). Всё, что можно проверить автоматически, уже проверяется: `go test ./...` и `-tags=integration` — см. [tests.md](tests.md). Здесь — только то, для чего нужен человек, настоящий клиент или настоящий контейнер.

Источник критериев: [carrel-spec.md](carrel-spec.md) §21, §23.6–§23.10.

**Критерий закрытия v1:** отмечены все пункты **P1–P5**; остальные — по возможности. Что остаётся сделать помимо этого списка — [roadmap.md](roadmap.md).

## Принципиальные проверки (обязательно для v1)

Автоматической замены нет; блокируют релиз v1.

| # | Проверка | Почему принципиально |
|---|----------|----------------------|
| **P1** | Заметка Carrel ↔ **jtx Board** (создание, правка, `X-`поля на месте после обеих правок) | §23.9 — заявленная совместимость. Фейковый сервер, соглашающийся с нами, не доказывает ничего |
| **P2** | Заметка Carrel ↔ **Evolution** (чтение и правка) | §23.9, то же на десктопе |
| **P3** | `docker compose` с пустым томом → setup → полный сценарий (A1–A3) | §21 развёртывание. Проверяется контейнер целиком: read-only корень, dropped capabilities, nonroot, healthcheck |
| **P4** | Логи `debug` без паролей и токенов после полного сценария (A5) | §21, §24.3. Тест проверяет строки, о которых догадался; человек читает то, что есть |
| **P5** | Вложение в заметку: вставка скриншота за пару секунд после настройки каталога | §23.10 говорит прямо: если медленно — функция мёртвая. Ни одно утверждение не измеряет «показалось мгновенным» |

## 1. Каркас и контейнер

Сборка с метаданными:

```bash
docker compose build \
  --build-arg VERSION=0.7.0 \
  --build-arg COMMIT=$(git rev-parse --short HEAD)
```

### A1. Пустой том → администратор

```bash
docker volume rm carrel_carrel-data   # если остался от прошлого прогона
docker compose up -d
```

- [ ] `http://127.0.0.1:8080/` ведёт на `/setup`
- [ ] Форма создаёт первого администратора и сразу открывает панель
- [ ] Повторный `/setup` ведёт на `/login`; второго администратора завести нельзя
- [ ] `docker compose ps` — `healthy` (healthcheck без shell, через `carrel healthcheck`)

### A2. Версия и коммит

- [ ] `/about` открывается без входа
- [ ] Версия и коммит совпадают с аргументами сборки выше
- [ ] Ссылка на исходники ведёт на репозиторий, лицензия названа AGPL-3.0-or-later

### A3. read-only корень и непривилегированный пользователь

```bash
docker compose exec carrel /carrel healthcheck
docker inspect --format '{{.HostConfig.ReadonlyRootfs}} {{.Config.User}} {{.HostConfig.CapDrop}}' <container>
```

- [ ] `ReadonlyRootfs` = `true`, пользователь `nonroot` (uid 65532), `CapDrop` = `[ALL]`
- [ ] Создание администратора и правка настроек проходят при read-only корне — пишется только том
- [ ] Порт слушается только на петле: с адреса хоста в сети — нет

### A4. SIGTERM

```bash
docker compose stop -t 20 carrel
```

- [ ] Запрос, выполнявшийся в момент остановки, завершается штатно
- [ ] В логах есть запись о завершении; без активных запросов процесс уходит быстрее 15 с
- [ ] После перезапуска сессии сброшены — вход требуется заново

### A5. Логи без секретов → **P4**

`CARREL_LOG_LEVEL: debug`, перезапуск, затем вход, создание и приём приглашения, смена пароля, тестовое письмо, подключение DAV-аккаунта, правка контакта, вложение в заметку:

```bash
docker compose logs carrel > /tmp/carrel.log
```

- [ ] Нет паролей, токенов приглашений, мастер-пароля, содержимого писем и карточек
- [ ] Логи структурированные (JSON), в stdout

### A6. Диагностика SMTP

- [ ] Неверный хост: «Send test email» показывает отказ соединения, а не «ошибка»
- [ ] Неверный пароль: показан ответ сервера на аутентификацию
- [ ] В выводе диагностики нет пароля реле
- [ ] С верными настройками письмо доходит, виден весь диалог

### A7. Письмо о восстановлении escrow

- [ ] Включить депонирование, создать пользователя, восстановить — пользователю уходит письмо
- [ ] Письмо нельзя отключить из панели
- [ ] При ненастроенном SMTP или без адреса панель говорит уведомить самому

### A8. Приглашение по ссылке без SMTP

- [ ] SMTP не настроен: админ создаёт ссылку (не email), копирует и передаёт
- [ ] В таблице доставка `link`, колонка Mail — `—`
- [ ] По ссылке пользователь сам выбирает логин, задаёт пароль и попадает внутрь
- [ ] Повторный переход по той же ссылке — «недействительно»

### A9. `THIRD_PARTY.md`

- [ ] Перечислены все зависимости из `go.mod` и вендоренный htmx с SSE-расширением
- [ ] Для каждой приведён текст лицензии; версии совпадают с `go.mod` и файлами в `internal/web/static/`

### Уже проверено локально (`go run`, не Docker)

Пройдено на dev-машине без контейнера. При финальной приёмке повторяется в Docker (это и есть смысл P3), но записано, чтобы не проверять дважды то, что уже вело себя правильно:

- [x] Пустой том → `/setup` → первый администратор → повторный `/setup` ведёт на `/login`
- [x] `/about` без входа; ссылка на исходники и лицензия на месте
- [x] Приглашение по ссылке при ненастроенном SMTP: логин выбирает приглашённый, повторный переход недействителен
- [x] Disable пользователя рвёт активную сессию сразу, не дожидаясь следующего запроса
- [x] `go test -race ./...` на dev-машине (Windows, MSYS2 UCRT64 gcc)

Не проверено даже локально: приглашение **по email** (нужен SMTP), A3–A7, A9.
